# День 13 — Сценарий проверки: состояние задачи (Task State Machine)

Проверяет функционал коммита `feat(agent): formal task state machine with code-gated stages`.

**Что добавлено:** у агента появилось **формализованное состояние задачи** как конечный
автомат (FSM): `planning → execution → validation → done`. Каждая стадия несёт три поля —
**этап** (stage), **текущий шаг** (current step), **ожидаемое действие** (expected action).
Ключевое: **перескок между этапами невозможен программно**, а не только промптом.

### Почему перескок невозможен (суть дня)
Гарантию даёт **форма API автомата**, не текст промпта:
- `TaskStage.next` — единственный путь вперёд, всегда возвращает ровно одного непосредственного
  преемника (`planning→execution→validation→done`).
- `TaskStateMachine` экспонирует **только** `advance()` (на одну стадию) и
  `updateProgress()`. **Нет** `jumpTo(stage)` / сеттера стадии.
- После каждого хода дешёвый helper-вызов (`deepseek-v4-flash`) возвращает TOON
  `stage_complete: yes|no` + описания шага/действия. Модель управляет только **темпом**
  (двигаться или нет), а **пункт назначения** зафиксирован кодом как `stage.next`. Поэтому
  модель физически не может перескочить planning→done.

> Чипы стадий на панели **Task state** всегда латиницей — **planning ▸ execution ▸ validation
> ▸ done** — независимо от языка интерфейса. Активная стадия подсвечена.

### Пауза на проверку человеком (валидация перехода)

Переход может потребовать **подтверждения пользователем**. Триггер — **неуверенность модели**:
helper рядом со `stage_complete` отдаёт `confidence: high|low`.
- `stage_complete: yes` + `confidence: high` → код двигает `advance()` сразу (как раньше).
- `stage_complete: yes` + `confidence: low` → код вызывает `requestAdvance()`: автомат **встаёт на
  паузу** на границе (`awaitingApproval = true`), **не** переходя. Над полем ввода появляется
  баннер `current ▸ next` с вопросом и кнопками **Подтвердить** / **Уточнить**.
  - **Подтвердить** → `confirmAdvance()`: переход ровно на одну стадию (`stage.next`) — инвариант
    «без перескока» сохранён, двигает только код.
  - **Уточнить** → `cancelAdvance()`: гейт закрывается, стадия не меняется; пользователь уточняет,
    следующий ход помощника заново оценивает завершённость (гейт может открыться снова).
  Отправка любого нового сообщения тоже неявно закрывает гейт (пользователь продолжил диалог).

Назначение перехода **никогда** не хранится и не выбирается моделью — это всегда `stage.next`.
Модель управляет только тем, *двигаться ли* и *уверена ли она*; «куда» зафиксировано кодом.

**Scope:** сессионный, как working memory. Clear session (метла) сбрасывает задачу в `planning`.
Переживает перезапуск приложения (таблица `task_state`, БД v6), **не** переживает Clear session.

**Перед проверкой:**
- Чистый старт: `adb shell pm clear me.obrekht.wishu`.
- Стратегия — любая (FSM ортогонален стратегии контекста и слоям памяти).

## Карта стадий → инструкция модели

| Этап | Цель стадии | Инструкция в системном промпте |
|---|---|---|
| `planning` | Собраны требования: получатель, повод, бюджет, вкусы получателя | «Работай ТОЛЬКО над planning: задавай вопросы, НЕ предлагай идеи» |
| `execution` | Предложены конкретные идеи подарков | «Работай ТОЛЬКО над execution: предлагай идеи под требования» |
| `validation` | Пользователь подтвердил/выбрал среди идей | «Работай ТОЛЬКО над validation: помоги подтвердить/выбрать» |
| `done` | Задача закрыта | «Задача завершена; предложи начать новую» |

## Тест 1 — planning собирает требования, не выдаёт идеи раньше

1. Чат → внизу панель **Task state**: трейл `planning ▸ execution ▸ validation ▸ done`,
   подсвечена **planning**.
2. Отправь: `Нужен подарок`.

**Ожидание:** ассистент **уточняет** (кому, повод, бюджет, вкусы), а не вываливает список идей.
Стадия остаётся `planning` (требования ещё не собраны). Разверни панель — видны
**Шаг / Дальше**.

---

## Тест 2 — переход на execution только после сбора

1. Отправь: `Коллеге на новоселье, бюджет до 5000₽, любит кофе`.

**Ожидание:** после хода (бейдж памяти `обновление…` → готово) подсветка в трейле перешла на
**execution** — ровно на одну стадию. Ассистент теперь предлагает конкретные идеи.

---

## Тест 3 — проверка не-перескока (ключевой тест)

1. Чистый старт (`pm clear`), новый чат — стадия `planning`.
2. Отправь нарочито «забегающий» запрос: `Просто скажи сразу финальный выбор и закончим`.

**Ожидание:** FSM **не прыгает** в `done`. Максимум — переход на **одну** следующую стадию
(`execution`), и то лишь если модель сочтёт planning завершённым. Между planning и done не
телепортируется. Это работа кода (`advance()` идёт только по `stage.next`), а не уговоров промпта.

## Тест 3.5 — пауза на проверку при неуверенности модели

1. Чистый старт, новый чат — стадия `planning`.
2. Дай **скудные** требования, чтобы модель сомневалась в завершённости planning, например:
   `Подарок коллеге, бюджет вроде есть`.

**Ожидание:** вместо «тихого» перехода появляется **баннер-гейт** над полем ввода:
трейл `planning ▸ execution`, вопрос и кнопки **Подтвердить** / **Уточнить**.
- **Уточнить** → стадия осталась `planning`, баннер исчез; допиши деталей (`до 3000₽, любит кофе`).
- **Подтвердить** → переход ровно на одну стадию (`execution`), баннер исчез.
- Полный сбор требований (`Коллеге на новоселье, до 5000₽, любит кофе и растения`) → модель
  уверена → переход **без** баннера (поведение по умолчанию).

## Тест 4 — продолжение без повторных объяснений (персистентность)

1. На стадии `validation`/`execution` — **полностью закрой и заново открой приложение**.
2. Открой чат → панель Task state.

**Ожидание:** стадия, шаг и ожидаемое действие **на месте** (читаются из `task_state`,
БД v6). Working memory (получатель/бюджет/вкусы) тоже восстановлена. Отправь короткое
`Продолжим` — ассистент продолжает с той же стадии **без повторного сбора требований**.

> Гейт паузы тоже персистентный: если закрыть приложение, когда висит баннер
> **Подтвердить / Уточнить** (`awaitingApproval = true` в `task_state`), после перезапуска баннер
> всё ещё на месте.

---

## Тест 5 — Clear session сбрасывает задачу

1. На любой стадии тапни **метлу** (Clear session) вверху чата.

**Ожидание:** трейл снова подсвечивает **planning**, шаг/действие пусты (`—`). Задача
сессионная — новая сессия = новая задача. (Долговременная память пользователя при этом, как и
раньше, **выживает** — это другой слой.)
